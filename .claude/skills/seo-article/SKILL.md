# SEO・AIO 記事作成

テーマ: $ARGUMENTS

検索上位に入り、AI 検索で引用される記事を作る。書き方のルールと理由は [references/seo-aio-rules.md](references/seo-aio-rules.md) にある。**執筆前に必ず読む。**

ユーザーに確認を取るのは2回だけ: ステップ3（戦略）とステップ7（投稿）。それ以外は止まらずに進める。

---

## ステップ1: 既存記事との重複確認

同じキーワードを狙う記事がすでにあると、2本が順位を食い合う。新規に書く前に確認する。

```bash
grep -l "<メインKWの主要語>" articles/*.md
grep -h "^title:" articles/*.md | grep "<主要語>"
```

- コンテンツ計画（memory の `project_content_plan.md`）で、どのピラーのクラスターになるかを決める
- 同じ検索意図の記事がある → 新規ではなく既存記事の改善を提案する（ステップ5以降を既存ファイルに対して行う）
- `$ARGUMENTS` が空ならテーマを聞く

## ステップ2: 調査（3エージェント並行）

Agent ツールで以下3つを **1つのメッセージで同時に** 起動する。各エージェントには WebSearch / WebFetch を使わせ、出典URL付きで返させる。

**A. 検索意図・SERP・ファンアウト**
- メインKWで検索し、上位10件の形式（定義型／ハウツー／リスト／比較）と検索意図を判定する
- AI Overview が出るか、出るなら何を答えていてどのサイトを引用しているか
- PAA（他の人はこちらも質問）、関連検索、サジェストからサブ質問を15個以上集める
- メインKWが AI モードでどんなサブ質問に分解されそうかを推定する（費用・違い・手順・事例・注意点・対象者など）
- 返すもの: 主検索意図、推奨形式、サブ質問リスト、共起語、AI Overview の引用元と答えの要旨

**B. 競合ギャップ**
- 上位3〜5記事の見出し構成（H2/H3）を WebFetch で取得する
- 全記事が扱っている必須トピック、どの記事も答えていない質問、古い・誤った情報を洗い出す
- 返すもの: 必須トピック一覧、差別化できる切り口3つ以上、競合の文字数の目安

**C. 一次情報**
- 官公庁・業界団体・調査会社の原典から、テーマに関する統計と制度情報を集める（2025〜2026年を優先）
- 孫引きではなく原典URLを取る。数値・調査名・発表年月・URLをセットで返す
- よくある誤解や、制度改正で古くなった情報も挙げる
- 返すもの: 引用可能なデータの表（数値／調査名／時点／URL）

## ステップ3: 戦略を提示して承認を得る

3エージェントの結果を統合して、以下を提示する。

```
## 記事戦略: <テーマ>

メインKW: / サブKW: / 主検索意図: / 推奨形式:
位置づけ: <どのピラーのクラスターか、内部リンク先>
推奨文字数: <競合の目安から>

### この記事だけの情報（情報利得）
- <競合にない切り口・自社試算・中小企業視点など>

### 構成案（H2/H3、見出しは検索クエリの形）
## 〇〇とは？…
### …
## よくある質問（7問）

### 引用する一次情報
- <数値 — 調査名（時点）URL>

### タイトル案（3案、32字前後、メインKWを前半に）
### slug 案（英小文字・ハイフン、既存と重複しない）
```

「この戦略で書き進めますか？」と聞く。承認されたら、以降は投稿確認まで止まらない。

## ステップ4: 執筆

[references/seo-aio-rules.md](references/seo-aio-rules.md) のルールに従って書き、`articles/YYYY-MM-DD-<slug>.md`（今日の日付）に保存する。

### フロントマター

```yaml
---
title: <32字前後。メインKWを前半に>
slug: <english-slug>
categories: [<既存カテゴリから選ぶ>]
tags: [<3〜6個>]
status: publish
excerpt: <100〜140字。メタディスクリプションになる。メインKWを含め、誰の・どんな悩みに・何が分かるかを書く>
---
```

`description` は書かない（post.py が送らない）。既存カテゴリは `grep -h "^categories:" articles/*.md | sort | uniq -c` で確認する。

### 本文の型

```markdown
<リード: 300字以内。読者の状況→この記事の答えの要旨→分かること。冒頭150字以内にメインKW>

> 本記事は [<ピラー記事タイトル>](/<pillar-slug>/) の関連記事です。   ← クラスター記事のみ

## 〇〇とは？<定義型の場合>

〇〇とは、△△のことです。<60字前後で言い切る定義文。次の文から補足>

## <サブ質問の形のH2>

<一文目でこのH2の問いに答える。続けて理由・根拠（出典リンク付き）・具体例>

| 比較・目安・費用は表 | … |
|---|---|

## <独自情報のH2: 中小企業の場合の判断基準／試算／向いていないケース など>

## よくある質問

### <質問？>

<一文目で直接答える（80字以内）。必要なら2〜3文で補足>

（7問。PAA とサブ質問のうち本文で扱わなかったものから選ぶ）

## まとめ

<要点3〜5個の箇条書き → 次の行動（診断・関連記事・相談）への導線>
```

守ること:
- 本文に H1（`# `）を書かない。見出しレベルを飛ばさない
- FAQ は `## よくある質問` ＋ `### 質問？` の形にする（テーマの FAQ 抽出がこの形しか拾わない）
- 内部リンク3本以上（ピラー・関連クラスター・サービス導線）。サイト内リンクは `/<slug>/` の相対パス
- 外部リンク（出典）2本以上。数値には出典か「当社試算」を付ける
- 本文に情報の時点（「2026年10月時点」など）を書く

## ステップ5: 自動点検

```bash
python3 .claude/skills/seo-article/scripts/check_article.py articles/<file>.md --kw "<メインKW>"
```

- ❌ ERROR は全部直す。終了コード0になるまで繰り返す
- ⚠️ WARN は1つずつ判断し、直すか、直さない理由を控える
- 機械で見られない項目は自分で確認する:
  - 各H2の一文目だけを読んで、見出しの問いに答えているか
  - 段落を1つだけ抜き出しても意味が通るか（「それ」「前述の」で始まっていないか）
  - 用語の表記ゆれがないか
  - ステップ3で挙げた情報利得が本文に入っているか

## ステップ6: ファクトチェック

[.claude/commands/fact-check.md](../../commands/fact-check.md) の手順を、保存した記事に対して実行する。確認は取らずに次のとおり直す。

1. 修正前に `articles/<file>.md.bak` を作る
2. ❌ 誤り → 正しい情報に書き換える／⚠️ 要注意 → 最新情報に直す／❓ 確認不能 → 削除する（「要出典」は残さない）
3. 直したらステップ5の点検をもう一度通す
4. `.bak` は投稿後に消す

## ステップ7: 結果を提示して投稿の承認を得る

```
## <タイトル>
ファイル: articles/<file>.md ／ 約N字 ／ FAQ N問 ／ 内部リンクN本 ／ 出典N本

点検: ERROR 0 / WARN N（残した WARN と理由）
ファクトチェック: 修正N件（主なもの）
情報利得: <この記事だけの情報>
```

「投稿しますか？」と聞き、承認されたら投稿する。

```bash
python3 post.py articles/<file>.md
```

出力に「画像生成エラー」があれば、その H2 の画像が欠けている。新規投稿のときに限り、もう一度 `python3 post.py` を実行して補う。

## ステップ8: 公開後の確認

公開URL（`https://hikitsugi.jp/<slug>/`）を取得して確認する。

```bash
curl -s https://hikitsugi.jp/<slug>/ | grep -oE '<title>[^<]*|name="description" content="[^"]*|name="robots" content="[^"]*|rel="canonical" href="[^"]*|"@type":"[A-Za-z]+"' | sort -u
```

- `<title>` と description が想定どおりか（description が excerpt になっているか）
- robots に `noindex` がないか、canonical が自分自身を指しているか
- 構造化データに BlogPosting があるか（投稿記事には現状 FAQPage・BreadcrumbList は出ない。固定ページのみ）

問題がなければ:
1. 関連する既存記事2〜3本に、新記事への内部リンクを追加する（追加したら post.py で更新。画像は再生成しない）
2. memory の `project_content_plan.md` に記事を追記する
3. ユーザーに公開URLを伝え、Search Console の URL 検査からインデックス登録をリクエストするよう伝える

コミット・デプロイはユーザーに頼まれたときだけ行う。
