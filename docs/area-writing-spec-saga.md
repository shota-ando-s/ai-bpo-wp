## 絶対に守ること

- **データファイルにない数値・事実を書かない。** 書きたい事実がデータにない場合は、WebFetch で一次情報（官公庁・自治体・公式サイト）を開いて確認できたときだけ書き、出典リンクを付ける。確認できなければ書かない。
- **架空の事例・実績・提携・顧客の声を書かない。** 試算は「当社試算」と明記し、前提を表で示す。
- **数値には、同じ文か直前の文に「時点」と「出典」を書く**（段落だけ抜き出されても正しいように）。表は直前の一文か表の下に出典と時点。
- 自治体名・制度名は正式名称。「市役所」「町役場」を正しく使い分ける（佐賀県に村はない）。
- 旧ブランド名「オフボード」は使わない。サービス名は「ヒキツギAI」、運営は「株式会社ふえん」（横浜市港北区）。「東京の会社」とは書かない。
- 今日は 2026年11月4日。補助金・事例・企業の確認日は「2026年11月4日時点」「2026年11月4日確認」。ファイル名の日付は 2026-11-04。
- 地名だけを差し替えたページにしない。市町ごとの固有データ（人口、産業、生成AIの導入状況、補助金、地元企業、主要産業での試算）で中身を変える。他の市町と同じ段落を使い回さない（「業務の引き継ぎにAIを使う」節も、その市町のデータで書き出しを変える）。**自分の担当ページ同士でも、書き終わったほかの担当のページとも段落を使い回さない。国の制度の表・相談先の表・試算の説明・FAQの回答も書き分ける。**
- **県の事業を市町の施策と書かない**（末尾の【D3】の一覧。佐賀県産業スマート化センター・佐賀県産業振興機構・佐賀県工業技術センター・窯業技術センター・よろず支援拠点・県の補助金・県のセミナーは県・県域の事業・機関）。**県庁・大企業の話と、中小企業が使える支援（研修・補助・相談）を分けて書く。**
- **大企業の工場（伊万里市の電子部品など）の話は、統計の値（出荷額の比率など）と会社名なしの1〜2文にとどめ、試算・業務の表・事例は中小企業の業種で書く**（【D1】）。秘匿の値（伊万里市の電子部品、玄海町・太良町の製造業計など）を推し量らない。
- **ベンダーが「AI」と呼ぶシフト作成・配車・オンデマンド交通・電話応答のサービスは、中身を書き添える**。生成AIと混同しない。
- **玄海原子力発電所（玄海町）**は、県・九州電力の資料の事実（号機ごとの状態）と時点だけを、玄海町のページと県ページに1〜2文。評価は書かない。AIの事例にしない。電源立地の交付金・原子力関係の給付・災害の制度は AI 導入の補助金の表・診断に入れない。**令和元年8月・令和3年8月の大雨（武雄市・大町町など）、吉野ヶ里遺跡・温泉などの観光地も、資料の事実と時点だけを書き、評価しない。** 観光の値は【D1】の書き方だけを使う。
- **国の出先機関は九州経済産業局（福岡市）・九州農政局（熊本市。県内は佐賀県拠点）・福岡財務支局（福岡市。県内は佐賀財務事務所）・佐賀労働局・九州運輸局（福岡市。県内は佐賀運輸支局）。** **佐賀財務事務所は九州財務局ではなく福岡財務支局の管内**（gov_ai.md）。「九州財務局佐賀財務事務所」「南九州財務局」「中国経済産業局」「中国四国農政局」「中国財務局」「岡山労働局」「佐賀農政局」「佐賀財務局」と書かない（**他県の仕様から写すと残る。置き換え漏れに注意**）。九州経済産業局のサイト（kyushu.meti.go.jp）はこのコンテナから 403 なので記事でリンクしない。
- **佐賀県知事は山口祥義（2015年1月就任。就任日は書かない）。** 知事の名前は県ページで1回まで。
- **他県の値（九州の他県・全国の他県）と並べない。** 県の値と市町の値を取り違えない（後継者不在率などを市町の値と書かない）。**TDB の九州・沖縄版の九州全体の値（人手不足・生成AI）を佐賀県の値と書かない。**

## 構成（H2 は次の順。見出しは検索クエリの形にする）

文字数の目安: **佐賀市 9,000〜11,000字、唐津市・鳥栖市・伊万里市 7,500〜9,500字、ほかの市 6,000〜9,000字、町 4,500〜7,000字**。無理に水増ししない。事例が見つからない節は短くてよい。同じ文章を使い回さない。

1. **リード（300字以内、H2なし）**: 一文目で「<市町名>の会社がAIで何をできるか」を、その市町の主要産業に即して言い切る。続けて箇条書き3点: 主要産業でAIに任せやすい業務／市町内・県内のAIの事例（実証・導入）／使える補助金（市町独自の制度の有無を一言）。最後に補助金診断 `/shindan/` と県ページ `/area/saga/` へのリンク。
2. `## <市町名>の会社はAIで何ができる？<主要産業>で効果が出やすい業務` — 経済センサスの業種構成、主要産業、有効求人倍率（**ハローワーク名と時点。管轄全体の値**。**ハローワーク別の原数値を使い、県全体の1.20倍〔季節調整値〕と並べない**。書き方は【D1】の「佐賀県の値」）、生産年齢人口の変化（【D1】の「人口」の書き方）を短く示し、業種ごとにAIで減らしやすい業務の表（3〜5行、列: 業種／AIに任せやすい業務／使うAIの種類〔生成AI・画像認識・予測など〕）。他県の値と並べない。
3. `## <市町名>・佐賀県のAI導入事例` — **実在の企業・自治体の事例だけ**。市町内の企業の事例 → 県内の同じ業種の事例、の順。各事例は「企業名（所在地・業種）／時期／何の業務にどんなAIを使ったか／効果（数値は出典の文言どおり）」と出典リンク。市町内に企業の事例がなければ「2026年11月4日の調査では、<市町名>の企業がAIを導入した公開事例は見つかりませんでした」と書き、県内の事例に進む。市役所の実証はここではなくH2 7で書く（重複させない）。
4. `## <主要産業>のAI活用事例：他の地域の会社は何に使っている？` — 県外の、その市町の**主要産業と同じか近い業種**の事例。書き方はH2 3と同じ。最後に「<市町名>の会社に当てはめると」として、どの業務から始めるとよいかを1段落で（当社の見方と明記）。県外の事例の割り当てがないページは、末尾の【D2】の「事例の割り当て」の書き方に従う（「見つからなかった」と短く書く）。**九州の他県の会社の事例は使わない**（九州の他県のページが使う）。
5. `## 試算：<市町名>の<主要業種>（従業員<N>名）でAIを入れた場合` — **業種・業態・規模・対象業務・人数・業務量は【D1】の割り当て表のとおり**（`data/area/saga/_calc.py` の PLAN。他県の PLAN と照合済みなので変えない。変えたいときは親に相談）。前提表（対象業務／対象人数と業務量〔仮定〕／削減率25%〔未検証の仮定〕／時間単価〔仮定。wages.md の業種の時給×1.2〕）と結果表（**月の削減時間／月の時間換算額〔年間〕の2行だけ**）。前提表に「<市町名>内の中規模の事業所の例（仮の会社）」と書く。**ヒキツギAIの月額・差し引き・初期費用の回収期間は書かない**（2026-10-24 ユーザー決定）。結果表の後に、(1) 削減率・人数・時間・時間単価は当社試算の仮定で当地の企業で測った値ではないこと、Noy & Zhang の[実験](https://pubmed.ncbi.nlm.nih.gov/37440646/)は参考資料でその業務の25%削減を実証したものではないこと、(2) **金額は業務余力の目安で、給与・残業代・外注費などの支出が同額減ることを意味しないこと、導入費・月額利用料・確認の時間は差し引いていないこと、回収期間は算出しないこと**、を書く（お手本: articles/2026-10-24-area-yamagata-higashine.md の試算の節。**文は写さず書き分ける**）。計算は python で確かめる。**結果表は見出しの行だけにせず、2行の中身を必ず入れる**（福島で4ページ抜けた）。試算の節で事例の会社に触れない（試算の会社が事例の会社の値と読まれないように）。出典行（時給の統計、Noy & Zhang の PubMed リンク https://pubmed.ncbi.nlm.nih.gov/37440646/ 、仮定である旨）。

### 事例の書き方（H2 3・4・7 共通）

- **実在の企業・自治体・事業だけ**を書く。一次情報（企業・自治体の公式発表、官公庁・公的機関の資料、報道機関の記事）で確認し、出典リンクを付ける。AIベンダーの導入事例ページは、導入先の企業名と内容が明記されていれば使ってよい（「◯◯社（AIベンダー）の導入事例による」と書く）。
- 効果の数値は出典の文言どおりに書き、時期を添える。数値がなければ書かない。**実証・見込み・目標・計画・理論値・テスト段階・精度・受講者の自己申告の数値は、そう書く**（【D2】の「事例ごとの数値の注意」）。
- 事例の企業を評価・推薦する言葉は使わない。ヒキツギAI・ふえんが関わった事例のように読める書き方をしない。
- 他地域の事例は、その市町の主要産業と同じか近い業種に限る。
- 同じ事例を複数の市町ページで詳しく書かない。【D2】の「事例の割り当て」で詳述と決めたページで詳しく書き、他のページでは1〜2文の要約と、そのページへのリンクにとどめる。**仕様が名指ししたページ以外では、他県で詳述した事例・企業に触れない。**
- **県・市の事業の成果報告・事例集・実証報告の事例**は掲載時点の紹介で、その後も使い続けているかは確かめていない。時点と出典を書く。開発・実証中のものを導入済みと書かない。研究・実証段階の精度を、導入の効果と書かない。
- **補助金の採択一覧にだけ出る企業**は「採択された」までにとどめ、効果や導入済みと書かない。
- **AIとほかの施策（RPA・クラウド・電話・ロボット・自動化設備）の効果が混ざる事例**は、AIだけの効果と書かない。出典が分けている効果だけをAIの効果として書く。
- 市町内に中小企業のAI事例がない場合は、そう明記したうえで、AI以外のDX事例を、AIではないと分かるように短く紹介してよい。
- URLに丸括弧を含むリンクは `%28` `%29` に置き換える（Markdownのリンクが途中で切れる）。
- 記事の出典リンクは**開けるものだけ**。九州経済産業局のサイトはこのコンテナから 403 を返す。書く前に WebFetch か curl（ヘッダーを偽らない）で開けるか確かめ、開けなければ使わない（このコンテナからは Internet Archive にも接続できない）。

### Web検索

WebSearch は**担当ごとに合計2回まで、できれば0回**（このセッションの残りは約90回）。データにない事実を足したいときは、データにある公式URLか確実に分かっている公式URLを WebFetch か curl（ヘッダーを偽らない）で開き、確認できたときだけ書く。佐賀新聞・日本経済新聞は会員限定で本文が読めないことが多い。読めた範囲だけ「◯◯新聞（日付）によると」と書く。県外の事例を足すときは、使う前に `grep -rl "<社名>" articles/ data/` で他県の使用を確かめる。**仕様の「見つからない」「確認できなかった」は、執筆担当が一次資料を開いて違えば直してよい**。直したときは報告に書く。

- 県・市町のサイトは、このコンテナの curl で切断・404 になることがある。WebFetch では開けることが多い。WebFetch は要約を返すので、数値は PDF を curl で保存して pdftotext で確かめる（pdftotext で日本語が出ない PDF は pdftoppm で画像にして読む）
