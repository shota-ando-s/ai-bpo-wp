# 地域AIメディアの更新手順

補助金診断（`/shindan/`）と地域ページ（`/area/` 以下）のデータを新しく保つための手順。データと仕組みはそろっているが、定期実行はまだ設定していない（2026-10-14時点）。

## データの置き場所

| データ | ファイル | 使っている場所 |
|---|---|---|
| 補助金・助成金（41制度） | `data/subsidies/*.yml` | 診断ツール（JSONに変換）、地域ページの補助金の表 |
| 地域の一覧 | `data/subsidies/areas.yml` | 診断ツールの都県・市区町村の選択肢 |
| 地域の統計（人手不足・事業承継・産業・人口・AI導入状況・自治体の施策） | `docs/area-local-data.md` | 地域ページの統計の表と冒頭の要約 |
| 業種別の試算の前提値 | `docs/area-industry-model.md` | 地域ページの試算の章 |
| 自治体の補助金の調査メモ | `docs/area-local-subsidies.md` | YAMLの根拠 |

地域ページの本文（`articles/2026-10-14-area-*.md`）は、上のデータを手で転記している。数値を変えたら本文も直す。

## 月1回：補助金の更新

1. 点検する。
   ```bash
   python3 scripts/check_subsidies.py --urls
   ```
   締切を過ぎた制度、来年度の公募時期になった制度、確認日が30日より古い制度、公式URLにアクセスできない制度が一覧で出る。
2. 出てきた制度の公式ページを確認し、`data/subsidies/*.yml` の `period`、`next_expected`、`max_yen`、`rate`、`checked`（確認日）を直す。新年度の公募が始まった制度は、上限・補助率・対象経費も確認し直す。
   - Claude Code に「`check_subsidies.py` の結果の制度を、公式ページで確認して YAML を更新して」と頼めばよい。
3. 診断ツール用のJSONを作り直す。
   ```bash
   python3 scripts/build_shindan_data.py
   ```
4. 地域ページの補助金の表（「今申請できる制度」「来年度の公募が見込まれる制度」）と、本文中の「◯年◯月◯日時点」を直す。
   ```bash
   python3 post.py articles/2026-10-14-area-kanagawa.md
   ```
5. コミットしてデプロイする（`./deploy.sh`）。

## 統計の更新時期

公表の時期に合わせて `docs/area-local-data.md` と地域ページを直す。

| 統計 | 発行元 | 更新の頻度・時期 |
|---|---|---|
| 有効求人倍率 | 各労働局 | 毎月（月末〜翌月初め） |
| 人手不足に対する企業の動向調査 | 帝国データバンク | 年4回（1・4・7・10月調査、2〜3か月後に発表） |
| 後継者不在率 | 帝国データバンク | 年1回（11月ごろ） |
| 社長の平均年齢 | 帝国データバンク | 年1回（2月ごろ） |
| 休廃業・解散 | 帝国データバンク | 年1回（1月に全国版、1〜2月に都県版） |
| 能力開発基本調査 | 厚生労働省 | 年1回 |
| 自治体の生成AI導入状況 | 総務省 | 年1回（4月ごろ） |
| 経済センサス‐活動調査 | 総務省・経済産業省 | 5年ごと。令和8年調査の結果は2027年以降 |
| 地域別将来推計人口 | 国立社会保障・人口問題研究所 | 5年ごと（次回は令和10年推計の見込み） |
| 横浜市・川崎市・埼玉県・さいたま市の中小企業調査 | 各自治体 | 不定期。特別調査のテーマにAI・DXが入ったときに更新 |

## 年1回：制度の新年度切り替え（4〜6月）

国・都県・市の補助金は、4〜6月に新年度の公募が始まる。この時期は、全制度について名称・上限・補助率・対象経費・締切を確認し直す。新しい制度が出ていないかも調べる（Claude Code に、都県・市ごとの調査を並行して頼む）。
