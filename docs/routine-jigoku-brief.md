# 企画書: 連載「#ルーティン地獄」

> 2026-11-08 起案（安藤さんとの壁打ちをもとに作成）。
> 公開先は kantan-ai.jp（かんたんAI）。記事は `articles/` に置き、各記事は seo-article スキルの手順（調査→戦略の承認→執筆→点検→ファクトチェック→投稿の承認）で作る。
> **未確定事項は末尾の「10. 未決事項」にまとめている。**

## 1. 目的

- **主目的：ふえんの考え方を伝える（思想・ブランド）。** 「全員がAIを使える」ことより「全員がAIの恩恵を受けられる」ことを目指す、という考え方を、具体的な業務の話で伝える。
- 副次的に、検索と AI 検索（AI Overview・ChatGPT・Perplexity）から読まれ、無料業務診断の相談につなげる。
- 検索で読まれ引用されることが、考え方を広める一番の手段になる。そのため記事は思想寄りでも、書き方は seo-article のルール（`.claude/skills/seo-article/references/seo-aio-rules.md`）に従う。

## 2. 読者

| 読者 | 状況 | 記事で届けたいこと |
|---|---|---|
| 中小企業の経営者 | 現場の手作業に、誰の時間が月何時間かかっているか見えていない | 作業の見える化と、任せるかどうかの判断基準 |
| 現場の事務・経理担当 | ツールを入れても毎月同じしんどい作業をしている | 「他社でも同じ」という共感と、作業がどう変わるか |

各記事に、両方の視点を入れる（「6. 記事の型」の H2 で分ける）。

## 3. 連載の主張（全記事で守る）

> ルーティン地獄は、担当者の能力や根性の問題ではない。道具が途中で止まる構造の問題である。
> AIを使いこなせなくても、その「止まった部分」を引き受ける仕組みがあれば、AIの恩恵は届く。

- 「ルーティン地獄」とは、ツールを入れても人の手に残った、毎月くり返すしんどい作業のこと。
- 担当者を責める書き方をしない。「やり方が古い」「ITに弱い」とは書かない。
- AIで全部が解決するとは書かない。**毎回「人が決めること」を明記する。** これを連載の誠実さとして差別化にする。

## 4. 4つの「止まる場所」（連載の分類）

既存ツール（Excel、RPA、OCR、SaaS）が止まる場所は4つに集約できる。2026-11-07 に公開事例・公的資料22件を整理して得た分類。

| 分類名 | 何が起きているか | 代表的な業務 |
|---|---|---|
| 形式バラバラ地獄 | 書類の形式が取引先ごとに違い、読み取り後の修正や取引先ごとの保守が残る | FAX注文書、受領した請求書、領収書 |
| 例外地獄 | ルールで処理できない例外が混ざり、そこだけ人に戻ってくる | 入金消込（部分入金・合算入金）、経費の規程外申請 |
| あと出し変更地獄 | 確定したあとに変更が入り、組み直しが発生する | シフトの再調整、日程のリスケ |
| 確認・聞き直し地獄 | 別の人・別の場所への確認や聞き取りが要る | 営業からの「注文届いてる？」、介護記録の聞き取り、見積の単価確認 |

1つの業務が複数の分類にまたがることはある。記事では一番効いている分類を主分類にする。

## 5. 連載の構成

```
ハブ記事: ルーティン地獄とは（4分類の紹介と連載の主張）
  ├── 形式バラバラ地獄 → FAX注文書、受領請求書、領収書…
  ├── 例外地獄 → 入金消込、経費精算…
  ├── あと出し変更地獄 → シフト再調整、日程調整…
  └── 確認・聞き直し地獄 → 社内照会、介護記録…
```

- 業務別の記事は冒頭でハブ記事へリンクし、ハブ記事は全業務記事へリンクする。
- 分類ごとの一覧ページは、記事が3本以上たまってから作るか決める。

## 6. 記事の型（業務別記事）

seo-article の「本文の型」に、連載の構成を当てはめる。見出しは検索クエリの形にする。

| H2（例：入金消込） | 書くこと |
|---|---|
| リード | 地獄の情景（月末の何時間、誰が、何をしているか）と、この記事の答えの要旨 |
| 入金消込が手作業で終わらないのはなぜ？ | 実際の声・公開事例の要約（出典つき）。一文目で答える |
| これまでの解決策で何が楽になった？ | Excel・会計ソフト・RPAなど、AI以前の解決策と効果 |
| それでも人の手に残る作業は？ | なぜ機械で止まるのか。4分類のどれに当たるか |
| AIに任せられるのはどこまで？ | 分担表（AIがやる／人が確認する／人が決める） |
| 経営者が見るべき数字は？ | 月何時間・誰の時間か。試算は「当社試算」と前提条件を書く |
| 小さく始めるなら何から？ | 最初の1歩と注意点（誤処理、個人情報、承認の設計） |
| よくある質問 | 7問。`## よくある質問` ＋ `### 質問？` の形 |
| まとめ | 要点3〜5個と、無料業務診断への導線 |

分担表の形（全記事で共通にする）:

| 作業 | AIがやる | 人が確認する | 人が決める |
|---|---|---|---|
| 例：明細と請求の突き合わせ | ○ | | |
| 例：候補が複数ある入金の判断 | 候補を出す | ○ | |
| 例：取引先への差額の問い合わせ | 文面の下書き | | ○ 送るかどうか |

### ② 例外地獄：入金消込

- タイトル案: 「入金消込が終わらない原因は？名義違い・合算入金とAIの分担」

- 内部リンク: ハブ記事、`/accounting-ai-bpo-guide/`（経理AI BPO）、`/ai-bpo-cost/`、無料業務診断

- タイトル案: 「FAX注文の入力がなくならないのはなぜ？OCR・RPA後に残る作業」
- slug 案: `routine-jigoku-fax-order`
- 仮KW: FAX 注文 入力 効率化 / FAX OCR 修正
- 内部リンク: ハブ記事、`/manufacturing-ai-bpo-guide/`、`/data-entry-ai-bpo-comparison/`、無料業務診断

## 8. 現場の声・事例の扱い

- **公開情報を要約し、匿名化して書く。** 対象は公開事例、官公庁の資料、公開投稿。出典は本文にリンクする。
- SNS の投稿は転載しない。引用するなら短く1件までにし、個人が特定できる情報は書かない。
- **架空の事例・実績・提携を書かない**（`memory/project_brand_name.md`）。ふえん自身の実績は、事実として確認できるものだけ書く。
- 「AIならこう分担できる」は事例ではなく当社の考えなので、「当社の考え」「想定例」と分かる書き方にする。
- 数値には出典と時点を付ける。自社試算は「当社試算」と前提条件を書く。確認できない数値は書かない。

## 9. 表記ルール

| 対象 | 使う表記 | 使わない表記 |
|---|---|---|
| 連載名（本文） | ルーティン地獄 | ルーチン地獄、ルーティーン地獄 |
| 連載名（SNS・タグ） | #ルーティン地獄 | — |
| 分類名 | 形式バラバラ地獄／例外地獄／あと出し変更地獄／確認・聞き直し地獄 | 言い換え（「イレギュラー地獄」など） |
| AIの呼び方 | AIエージェント（初出で「頼めば最後まで作業を進めるAI」と補足） | AI-エージェント、AI Agent |
| サービス名 | かんたんAI | ヒキツギAI、オフボード |
| CTA | 無料業務診断（`/contact/`） | 無料相談、無料診断（表記を混ぜない） |

使わない言い回し:

- 「AIで全部自動化」「人手ゼロ」「誰でも簡単に」など、人が決める部分を消す表現
- 「業界No.1」「必ず」「最安」など根拠のない最上級表現
- 担当者を責める表現（「アナログな人」「ITに弱い現場」）

WordPress の設定:

- カテゴリ: `AI業務自動化`（既存）
- タグ: `ルーティン地獄` を全記事に付ける（連載の目印）。ほかに業務名・分類名を2〜4個
