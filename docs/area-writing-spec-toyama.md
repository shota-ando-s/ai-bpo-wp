## 絶対に守ること

- **データファイルにない数値・事実を書かない。** 書きたい事実がデータにない場合は、WebSearch/WebFetch で一次情報（官公庁・自治体・公式サイト）を開いて確認できたときだけ書き、出典リンクを付ける。確認できなければ書かない。
- **架空の事例・実績・提携・顧客の声を書かない。** 試算は「当社試算」と明記し、前提を表で示す。
- **数値には、同じ文か直前の文に「時点」と「出典」を書く**（段落だけ抜き出されても正しいように）。表は直前の一文か表の下に出典と時点。
- 自治体名・制度名は正式名称。「市役所」「町役場」「村役場」を正しく使い分ける。
- 旧ブランド名「オフボード」は使わない。サービス名は「ヒキツギAI」、運営は「株式会社ふえん」（横浜市港北区）。「東京の会社」とは書かない。
- 今日は 2026年10月25日。補助金・事例・企業の確認日は「2026年10月25日時点」「2026年10月25日確認」。ファイル名の日付は 2026-10-25。
- 地名だけを差し替えたページにしない。市町村ごとの固有データ（人口、産業、生成AIの導入状況、補助金、地元企業、主要産業での試算）で中身を変える。他の市町村と同じ段落を使い回さない（「業務の引き継ぎにAIを使う」節も、その市町村のデータで書き出しを変える）。**自分の担当ページ同士でも段落を使い回さない。国の制度の表・相談先の表・試算の説明・FAQの回答も書き分ける。**
- **県の事業を市町村の施策と書かない**（末尾の「富山県のデータの補足」の一覧）。
- **ベンダーが「AI」と呼ぶシフト作成・配車・オンデマンド交通のサービスは、中身を書き添える**。生成AIと混同しない。
- **能登半島地震（2024年1月1日）は、国・県・市の資料で確かめた事実（被害・支援制度）だけを、時点つきで書く。** 復旧の評価・感想・応援の言葉は書かない。災害の支援制度（なりわい再建支援補助金など）は、AI導入に使える補助金の表に入れない（末尾の「決めたこと」）。
- **「北陸経済産業局」と書かない。** 国の出先は「中部経済産業局」（窓口は中部経済産業局北陸支局）。
- **「富山のインテック」と書かない。** インテックは2026年7月1日に TIS と合併し、TISI株式会社（本社 東京都新宿区）になった（末尾の「地元IT企業の扱い」）。

## 構成（H2 は次の順。見出しは検索クエリの形にする）

文字数の目安: **富山市 8,000〜11,000字、他の市 6,000〜10,000字、町村 4,000〜7,000字**。無理に水増ししない。事例が見つからない節は短くてよい。同じ文章を使い回さない。

1. **リード（300字以内、H2なし）**: 一文目で「<市町村名>の会社がAIで何をできるか」を、その市町村の主要産業に即して言い切る。続けて箇条書き3点: 主要産業でAIに任せやすい業務／市内・県内のAIの事例（実証・導入）／使える補助金（市独自の制度の有無を一言）。最後に補助金診断 `/shindan/` と県ページ `/area/toyama/` へのリンク。
2. `## <市町村名>の会社はAIで何ができる？<主要産業>で効果が出やすい業務` — 経済センサスの業種構成、主要産業、有効求人倍率（**ハローワーク名と時点。管轄全体の値**。就業地別の市町村の値は公表された上位5市町だけ）、生産年齢人口の2050年見込み（社人研、当社算出）を短く示し、業種ごとにAIで減らしやすい業務の表（3〜5行、列: 業種／AIに任せやすい業務／使うAIの種類〔生成AI・画像認識・予測など〕）。職業別の有効求人倍率を使うときの注意は末尾の「新潟県までと違うところ」。他県の値と並べない。

5. `## 試算：<市町村名>の<主要業種>（従業員<N>名）でAIを入れた場合` — 業種は wages.md にある業種から選ぶ（農業・漁業は毎月勤労統計に時給がないので、米の集出荷・直販なら「卸売業・小売業」、ます寿司・かまぼこなら「製造業」のように統計がある業種で試算し、その旨を前提表に書く）。主要業種はその市町村で従業者か出荷額が大きい業種を選ぶ（他の市町村と業種・規模・対象業務をできるだけ変える。末尾の表の「試算の業種の目安」）。対象業務は H2 3・4 の事例に近いものにする。前提表（対象業務／対象人数と業務量〔仮定〕／削減率25%〔未検証の仮定〕／時間単価〔仮定。wages.md の業種の時給×1.2〕）と結果表（**月の削減時間／月の時間換算額〔年間〕の2行だけ**）。**ヒキツギAIの月額・差し引き・初期費用の回収期間は書かない**（2026-10-24 ユーザー決定）。結果表の後に、(1) 削減率・人数・時間・時間単価は当社試算の仮定で当地の企業で測った値ではないこと、Noy & Zhang の[実験](https://pubmed.ncbi.nlm.nih.gov/37440646/)は参考資料でその業務の25%削減を実証したものではないこと、(2) **金額は業務余力の目安で、給与・残業代・外注費などの支出が同額減ることを意味しないこと、導入費・月額利用料・確認の時間は差し引いていないこと、回収期間は算出しないこと**、を書く（お手本: articles/2026-10-24-area-yamagata-higashine.md の試算の節。**文は写さず書き分ける**）。計算は python で確かめる。**結果表は見出しの行だけにせず、2行の中身を必ず入れる**（福島で4ページ抜けた）。**書き終わったページ（articles/2026-10-25-area-toyama-*.md）の試算の表を見て、月の削減時間・削減額が同じにならないよう前提（人数・業務量・業種）を変える。** 出典行（時給の統計、Noy & Zhang の PubMed リンク https://pubmed.ncbi.nlm.nih.gov/37440646/ 、仮定である旨）。

### 事例ごとの数値の注意（実証・見込み・目標・理論値・テスト、AIとほかの施策の効果が混ざる事例）

- 効果の数値は出典の文言どおりに書き、時期を添える。数値がなければ書かない。**実証・見込み・目標・理論値・テストの数値は、そう書く**（丸喜産業の「熟練作業員で約33%・経験の浅い作業員で約50%短縮」は2024年9月の**実証**の値で、本番の運用の効果ではなく、何時間から何時間か・何件で測ったかは書かれていない〔リリースの副題の「半減」だけを書かない。33%と50%の両方を書く〕、湖北精工の「AI認識率99%・サイクルタイム5.26秒」は借りたテスト用ロボットでの**検証**で量産の工程の時間・人数の効果ではない、岡本の「熟練作業者の判断と一致する割合71〜80%」は**PoC**（10項目）で時間・不良率の削減の数値はない、髙橋金属の「正解率80.3%→97.7%」は比較**実験**の値で「検査員3人→1人」は**目標**〔不良を良品と判定する誤りが4.6%残る〕、伸和の「スケジュール立案作業の半減」は「目途がついた」段階の**見込み**〔生産数は28.0→28.3ロット/日でほぼ増えていない〕、槌谷の「年間2,382時間・448万円・94%削減」「フードロス年1,654万円」はどちらも「見込む」で**見込み**、デリカスイトの「26%・292時間・116.8万円」「原材料ロス約1,609.6万円」は「検証結果を基にした**理論値**」、心結の「予測誤差20%以内」は**目標**の書き方、黒田製作所の「1日150分→75分」は「平均15型/1日」での**換算**〔1型10分→5分が実装後の値〕、エイ・エム・シィの「60分→10分」は1回あたりで月の回数は書かれていない、サンテクノスの「検査時間50%削減」は算出の方法〔品目・期間〕が書かれていない・「不良流出率0%」とあわせて過検出が残ると書かれている、更紗ホテルズの「半分」はメールの**件数**で時間ではない〔期間も書かれていない〕、長浜シャーリング工場の「3時間/日→50分/日」は何日の平均か書かれていない）。

### 補助金診断のデータ

`data/subsidies/toyama.yml` は subsidy_a.yml（28制度）と subsidy_b.yml（4制度）を結合した32制度（すべて confidence: official）。冒頭のコメントは新潟・福島の形（元データ・件数・AIを名指しした制度・addon・入れなかった制度）に合わせ、次を書く:
- 県のAI導入枠は今年度終了。県で受付中の IT・AIツール導入の補助はない。市町村でAIを名指しは小矢部市の生成AI活用支援事業補助金だけ
- 国の補助金への上乗せは黒部市の2区分（shoryokuka-ippan・hatarakikata、cost_ratio）。県の賃上げサポート補助金と黒部市の業務改善事業・販路開拓事業は、上乗せ先が national.yml にないので入れていない（または note）
- 能登半島地震の支援制度（なりわい再建支援補助金など）はAI導入向けでないので入れていない

結合するときに直したほうがよい点（どれも診断ツール shindan.js の計算の仕方から。判断は下の「判断が必要な点」）:

1. **立山町（toyama-tateyama-shoryoku）の addon を外し、単独の制度として入れる**。shindan.js は、上乗せの制度（status now）を「来年度に使える組み合わせ」でも上乗せ先と組み合わせる（plan の `it.status === 'now' || it.status === group`）。digital-ai-donyu は `fuenn_available_from: 2027-04` で「来年度」扱いなので、立山町は「来年度の国の補助金＋立山町の上乗せ」として計算されるが、町の要綱は2027-03-31失効で、12-31までに支払い完了が条件 → 実際にはありえない組み合わせになる。また町の対象は購入費だけなのに、診断の対象経費は「初期費用＋月額×月数」で月額も含む。案: `addon`・`stacking` を削り、`rate_num: 0.5`・`max_yen: 200000`・`min_cost_yen: 50000`・`small_only: true` は残し、`targets.efficiency` を ○ → **△**（月額利用料が対象外で、クラウド型のAIツールには使いにくい）。note に「（経費−国の補助額）×1/2 の控除の規定がある」と残す
2. **小矢部市 DX推進補助金（toyama-oyabe-dx）の addon を外す**。addon がある制度は単独の補助額を計算しない（calc が amount: null を返す）ため、今年度単独で使える1/2・10万円の制度が「今年度に使える組み合わせ」に出ない。上乗せ先（県のトランスフォーメーション補助金）は今年度終了で next_expected もないので、上乗せとして計算される場面もない。案: `addon`・`stacking` を削り `rate_num: 0.5` を足す。「県の補助金などと併用でき、他の補助の残りに上乗せする」は note・fuenn_note に残す
3. **小矢部市 生成AI（toyama-oyabe-genai）の上限の区分**: 診断は小規模事業者の別の上限を表せない（rate_small_num は補助率だけ）。`max_yen: 100000` のままだと、小規模事業者に10万円まで出る計算になる（実際は5万円）。案A: `max_yen: 50000` にして中小企業は少なめに出る（過大に出さない）。案B: 10万円のまま note に「小規模事業者は5万円」。あわせて `max_months: 4` を足す案（対象は2027年2月利用分までで、11月に交付決定・契約なら11〜2月の4か月。診断の月数入力が12か月でも4か月分で計算される）
4. 魚津市 エネルギー効率化（toyama-uozu-energy）は addon_to が県の制度（今年度終了、next_expected なし）で、組み合わせの計算には出ない。カードは「今申請できる」の△で出る。県の補助を受けた事業者だけが使えることは note・fuenn_note にある → そのままでよい
5. 黒部市の2区分は、shoryokuka-ippan が締切済み（next_expected なし）のため組み合わせの計算には出ず、hatarakikata への上乗せは targets がすべて△なので計算に使われない（福島のいわき市と同じ扱い）→ そのままでよい
