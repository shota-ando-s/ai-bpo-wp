2026-11-08 にユーザーと企画を決めた。企画書は `docs/routine-jigoku-brief.md`。

- SNS漫画シリーズ「ルーティン地獄」（「引き継ぎ地獄」の姉妹企画）と対になる記事。漫画は共感と余韻で解決策を出さない。記事は構造を解きほぐし、やめる・AIと分担するを示す。
- シリーズ名は最有力だが正式決定ではない。
- 主目的は思想・ブランド（「全員がAIの恩恵を受けられる」）。検索流入と無料業務診断は副次。書き方は seo-article のルールに従う。
- 読者は中小企業の経営者と現場の事務・経理担当。各記事に両方の視点を入れる。誰も悪者にしない。
- 2つの型: 型A（続ける理由がなくなった業務 → まずやめる）、型B（手作業が残る業務 → AIと分担）。型Bの止まる場所は 形式バラバラ地獄／例外地獄／あと出し変更地獄／確認・聞き直し地獄。
- 現場の声は原文で確かめてから書く。紹介記事と当事者の投稿を分け、事実と当社の仮説を分ける。架空の事例は書かない（[[brand-name-kantan-ai]]）。
- まず3本で様子を見る: ハブ（routine-jigoku）、入金消込、Excelの転記。FAX注文書は manufacturing-ai-bpo-guide とカニバリしやすいので4本目以降。

**Why:** ユーザーの依頼。ふえんの考え方を、具体的な業務の話で伝えるため。

**How to apply:**
- 連載の記事を書くときは、企画書の「記事の型」「表記ルール」に従い、seo-article のステップ2から進める。
- タグ `ルーティン地獄` を全記事に付ける。カテゴリは `AI業務自動化`。
- 記事タイトルは業務の言葉を前半に置く。「ルーティン地獄」は検索されにくく、日常生活の習慣と誤解されやすい。
- FAX 注文書の記事は `manufacturing-ai-bpo-guide` とカニバリしやすい。書くときは検索意図の重なりを確かめる。
- 記事を公開したら企画書の「最初の3本」と [[ai-bpo-content-plan]] に進捗を書く。
